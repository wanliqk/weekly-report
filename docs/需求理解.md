# 个人日报周报管理系统需求文档（第一版）

## 需求概述

建设一个面向个人使用的日报、周报管理系统。用户可按工作日期创建日报草稿，基于模板填写内容，经过提交和归档后沉淀为可查询、可导出的个人工作记录；系统可按指定自然周汇总日报并生成周报，周报生成后允许人工补充和修订。系统同时保留企业微信日报同步入口及后续扩展边界，但本期不连接企业微信，也不执行实际同步。

## 用户与使用场景

- 目标用户：需要持续记录每日工作并按周整理汇报的个人用户。
- 日常记录：用户每天创建或继续编辑当日（也可选择其他工作日期）的日报草稿，填写后提交、归档。
- 历史检索：用户按日期范围、状态等条件查找过往日报，并查看详情。
- 记录导出：用户选择已归档日报导出为 Excel，作为离线留存或二次整理材料。
- 周度汇总：用户选择一个自然周，系统汇总该周日报生成周报，再由用户人工补充、修订和保存。
- 模板维护：用户调整后续日报使用的字段、顺序等配置，以适应个人记录习惯。

## 核心业务对象与规则

### 日报

- 每份日报归属于一个工作日期；默认约束为同一用户、同一工作日期仅有一份日报。
- 日报生命周期为“草稿 → 已提交 → 已归档”。草稿可反复保存；提交表示内容填写完成；归档表示内容成为正式个人记录。
- 已归档日报默认只读，避免历史记录被无意修改；是否支持撤回归档列为待确认项。
- 日报记录创建时保存当时的模板字段快照。后续修改模板不得改变既有日报的字段、内容或展示结果。
- 日报至少记录：工作日期、模板字段及内容、当前状态、创建时间、更新时间、提交时间、归档时间。

### 日报模板

- 系统初始化一套默认日报模板，包含“今日工作内容”和“明日工作计划”两个内容项。
- 用户可以维护用于新建日报的模板，包括新增字段，以及调整字段名称、说明、顺序、是否必填和启用状态。
- 第一版暂定两个默认内容项为核心字段，可以调整展示配置，但不得同时停用或删除；该规则需用户确认。
- 模板调整仅影响调整后新建的日报，不追溯修改已经创建的日报。

### 周报

- 周报以用户指定的自然周为统计周期。第一版暂定自然周为周一 00:00 至周日 23:59（Asia/Shanghai）。
- 周报主要汇总该自然周内已归档日报；未归档日报不作为正式汇总来源，并在生成时提示用户。
- 周报生成内容应能追溯到来源日报，至少保留统计周期、来源日报标识/日期及生成时间。
- 同一自然周默认仅保留一份当前周报，防止重复生成造成记录混乱。
- 自动汇总结果生成后可由用户人工补充和修订；保存人工修订时不得反向修改来源日报。
- 如提供“重新生成”，必须在覆盖人工修订前明确提示并由用户确认；具体采用覆盖还是版本留存列为待确认项。

## 输入与输出

### 输入

- 日报工作日期。
- 日报模板字段配置。
- 日报各字段的文本内容。
- 日报查询条件，如日期范围和状态。
- Excel 导出的日报选择范围。
- 周报对应的自然周及人工补充、修订内容。

### 输出

- 可保存、提交、归档和查看的日报记录。
- 满足筛选条件的日报列表和日报详情。
- 包含已归档日报数据的 Excel 文件。
- 指定自然周的自动汇总周报及人工修订后的周报内容。
- 企业微信同步功能入口及“本期暂不可用”的清晰状态说明。

## 功能需求

### P0 - 必须实现

- [ ] 日报草稿创建：用户可选择工作日期，按当前启用的日报模板创建草稿；同一工作日期重复创建时应进入已有日报或给出明确提示。
- [ ] 日报草稿编辑与保存：用户可填写模板字段并多次保存，刷新或重新进入后内容不丢失。
- [ ] 日报提交：系统校验必填字段，通过后将草稿变更为已提交并记录提交时间；校验失败时明确标出缺失内容。
- [ ] 日报归档：用户可将已提交日报归档，系统记录归档时间，并将其纳入正式历史记录和周报数据来源。
- [ ] 日报列表与详情：用户可查看日报的工作日期、状态、更新时间等摘要，并进入详情查看完整字段内容。
- [ ] 日报查询：用户可至少按工作日期范围和状态筛选日报，并可清除筛选条件恢复完整列表。
- [ ] 默认日报模板：系统首次使用时提供“今日工作内容”和“明日工作计划”两个内容项，用户无需配置即可创建日报。
- [ ] 日报模板配置：用户可新增字段，并调整字段的名称、说明、顺序、是否必填和启用状态；保存后用于新建日报。
- [ ] 模板快照：日报创建后不因模板后续修改而丢失字段或改变历史内容。
- [ ] 已归档日报 Excel 导出：用户可按筛选结果或勾选记录导出已归档日报；非归档记录不得混入导出结果。
- [ ] 自然周选择：用户可指定一个自然周查看其起止日期及可用日报情况。
- [ ] 周报自动生成：系统按指定自然周汇总已归档日报，生成结构清晰、可继续编辑的周报初稿。
- [ ] 周报编辑与保存：用户可在自动汇总结果基础上补充、修订并保存，且不改变来源日报。
- [ ] 周报查询与详情：用户可按自然周查看已生成周报及其当前内容。
- [ ] 企业微信同步占位：日报相关页面保留同步入口；用户触发时仅提示“功能暂未开放”，不得调用外部接口或宣称同步成功。

### P1 - 重要功能

- [ ] 操作确认与反馈：提交、归档、重新生成等关键操作提供明确确认或结果反馈，避免误操作。
- [ ] 未归档提示：生成周报时展示该周草稿、已提交但未归档日报的数量或日期，帮助用户补齐记录。
- [ ] 空数据处理：没有日报的自然周仍可创建空白周报并人工填写，同时明确提示本次没有可汇总日报。
- [ ] 导出可读性：Excel 包含工作日期、各模板字段、状态及关键时间等列；动态模板字段应有稳定、可理解的列名。
- [ ] 数据追溯：周报详情可查看本次汇总所依据的日报日期或跳转到来源日报。

### P2 - 可选功能

- [ ] 日报快速复制：可复制上一工作日或指定日报的内容创建新草稿。
- [ ] 周报生成预览：保存前预览来源日报和汇总结果。
- [ ] 周报版本记录：保存自动生成及人工修订的历史版本，并支持比较或恢复。
- [ ] 更多导出方式：支持周报 Excel/PDF 或日报自定义列导出。
- [ ] 企业微信实际同步：在后续版本完成授权、字段映射、提交、结果记录及失败重试。

## 非功能需求

- 易用性：首次进入即可使用默认模板创建日报；核心操作名称和状态含义一致，错误提示应说明原因和处理办法。
- 数据完整性：日报状态变更、模板快照、周报来源关系和人工修订内容必须可靠保存；重复点击不得产生重复日报、重复归档或重复周报。
- 性能：在个人常规数据规模下，列表查询、日报保存、周报读取等常用操作应在 2 秒内反馈；Excel 生成应展示处理中状态并在合理时间内完成。
- 安全与隐私：工作记录只对当前用户可见；输入、查询和导出接口需校验访问权限，避免越权读取或修改数据。
- 可恢复性：保存失败、网络异常或导出失败时不得错误变更状态，应保留用户已填写内容并允许重试。
- 可维护性：模板字段和企业微信同步能力应具备稳定的数据标识及清晰边界，以支持后续扩展，而不破坏既有日报数据。
- 兼容性：具体运行平台、浏览器或移动端适配范围尚未确定，需在方案设计前确认。

## 边界与约束

- 本期不实现企业微信授权、接口调用、真实同步、同步结果回写及失败重试。
- 本期面向个人记录，不包含团队成员管理、上下级审批、评论、抄送、催办、组织统计或绩效评估。
- 本期不包含从企业微信或其他系统导入历史日报。
- 本期不要求智能总结、自然语言润色或其他 AI 生成功能；周报自动生成以规则化汇总日报为基础。
- 本期 Excel 导出范围仅包含已归档日报；周报导出属于可选扩展。
- 技术栈、部署方式、数据存储方式、备份策略及用户身份认证方式尚未指定，将在方案设计阶段确认。
- 系统时区第一版暂按 Asia/Shanghai，自然周暂按周一至周日计算。

## 验收标准

### 日报创建、保存与唯一性

- Given 用户尚未创建某工作日期的日报，When 用户选择该日期并创建，Then 系统使用当前启用模板生成草稿，并展示“今日工作内容”和“明日工作计划”。
- Given 某工作日期已经存在日报，When 用户再次尝试为同一日期创建，Then 系统不产生重复记录，并引导用户查看或编辑已有日报。
- Given 用户在草稿中填写内容并保存，When 用户刷新页面或重新进入该日报，Then 已保存字段及内容完整恢复。

### 日报提交与归档

- Given 草稿存在未填写的必填字段，When 用户提交，Then 系统阻止提交、保持草稿状态并指出缺失字段。
- Given 所有必填字段均符合要求，When 用户提交日报，Then 日报状态变为已提交，并记录准确的提交时间。
- Given 日报处于已提交状态，When 用户确认归档，Then 日报状态变为已归档、记录归档时间，并可用于查询、导出和周报汇总。
- Given 日报未处于已提交状态，When 用户尝试直接归档，Then 系统拒绝操作并说明允许的前置状态。

### 日报模板

- Given 用户未做任何模板配置，When 首次创建日报，Then 系统默认展示两个内容项且可正常填写和保存。
- Given 用户新增字段并调整字段顺序后保存模板，When 创建下一份日报，Then 新日报按最新配置展示字段及顺序。
- Given 某日报已经创建，When 用户修改或停用其来源模板中的字段，Then 该日报原有字段和值保持不变并仍可正常查看。

### 日报查询

- Given 系统中存在不同日期和状态的日报，When 用户设置日期范围和状态条件，Then 列表只显示同时满足条件的记录。
- Given 用户清除筛选条件，When 列表重新加载，Then 系统恢复显示当前用户的全部日报，并保持明确排序。

### Excel 导出

- Given 用户选择了一组已归档日报，When 发起导出，Then 系统生成可被常用 Excel 软件正常打开的文件，且每份日报的数据完整、列名清晰。
- Given 导出选择中包含草稿或已提交未归档日报，When 发起导出，Then 系统排除或拒绝这些记录并明确提示，不得将其写入归档导出文件。
- Given 不同日报使用过不同版本模板，When 合并导出，Then 各日报已有字段和值不丢失，缺少某字段的记录以空值呈现。

### 周报生成与修订

- Given 指定自然周内存在已归档日报，When 用户生成周报，Then 系统只汇总工作日期位于该周的已归档日报，并记录来源日期和生成时间。
- Given 指定周存在草稿或已提交未归档日报，When 用户生成周报，Then 系统不把这些日报作为正式来源，并清晰提示其数量或日期。
- Given 指定周没有已归档日报，When 用户创建周报，Then 系统提示无可汇总数据，并允许用户创建、编辑和保存空白周报。
- Given 周报已自动生成，When 用户补充或修改内容并保存，Then 再次打开时显示修订后的内容，来源日报内容保持不变。
- Given 同一自然周已存在周报，When 用户再次请求生成，Then 系统不静默创建重复周报或覆盖人工内容，而是提供查看现有周报或确认重新生成的路径。

### 企业微信同步占位

- Given 用户看到企业微信同步入口，When 用户点击该入口，Then 系统明确提示功能暂未开放，不发起任何企业微信请求，也不改变日报状态。

### 异常与权限

- Given 日报保存、状态变更或导出过程中发生网络或服务异常，When 操作失败，Then 系统显示失败原因或重试提示，不错误显示成功，不产生重复数据。
- Given 用户请求访问不属于自己的日报、模板、周报或导出结果，When 系统处理请求，Then 拒绝访问且不泄露记录内容。

## 待确认问题与当前假设

1. 运行形态：是桌面浏览器 Web 系统、移动端 H5、小程序，还是需要多端适配？Electron
2. 用户身份：是否需要账号登录，还是仅供本机单人使用？需要登陆。认证方式：JWT (24h 有效期，密码修改后自动失效)，支持多用户角色 (admin/user)
3. 日报日期：是否允许补写未来日期或历史日期？允许补写未来日期或历史日期，但是如果当日已经存在已归档的日报则不可补写。
4. 状态流转：已提交是否必须由用户再次操作才归档？已提交或已归档是否允许撤回？本文暂按提交、归档为两个独立动作，归档后只读。系统支持设置提交后自动归档。
5. 默认字段：两个默认内容项能否删除、停用或改名？本文暂按核心字段不可同时停用或删除，但允许调整展示配置。
6. 字段类型：除多行文本外，模板是否需要单行文本、数字、日期、单选、多选或附件？本文暂不限定具体字段类型。
7. 周报结构：期望按日期罗列，还是归并为“本周完成/下周计划/问题风险”等栏目？本文只要求规则化、可编辑汇总，具体格式待确认。
8. 周报来源：是否应纳入“已提交但未归档”的日报？本文暂以已归档日报作为唯一正式来源。
9. 重新生成：周报人工修改后再次生成，是覆盖、合并还是创建新版本？本文要求不得静默覆盖，具体策略待确认。
10. Excel 规格：是每份日报一行、每份日报一个工作表，还是需要固定企业格式？本文暂按适合筛选统计的表格导出，具体列结构待设计。
11. 数据规模与保留：预计日报年限、单次最大导出数量，以及是否需要定期备份或永久保留尚未明确。

## 需求确认重点

- 确认日报的三阶段状态流转以及归档后的修改规则。
- 确认两个默认模板字段是否允许删除、停用、改名，以及第一版所需字段类型。
- 确认自然周定义、周报结构、汇总来源及重新生成策略。
- 确认产品运行平台、登录方式和 Excel 输出格式。
