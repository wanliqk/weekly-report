## 1. 产品目标

建设一套面向 Windows 桌面的多用户日报周报管理系统。用户通过模板记录日报，经提交、归档后形成正式记录；系统按自然周汇总已归档日报生成可编辑周报，并支持归档日报 Excel 导出。第一版保留企业微信入口，但不连接任何企业微信接口。

## 2. 用户与权限

| 角色 | 能力 | 数据边界 |
|---|---|---|
| `user` | 管理自己的模板、日报、周报、导出和个人设置 | 仅本人数据 |
| `admin` | 具备普通用户能力；创建、编辑、禁用用户、重置密码和执行整库手动备份 | 默认不能通过业务接口查看其他用户的日报、周报和导出内容；整库备份属于受控运维能力 |

系统首次启动时创建第一个管理员。必须阻止禁用或降级最后一个有效管理员。

## 3. V1 功能范围

### 3.1 P0：必须交付

- 首次初始化、登录、退出、修改密码与 24 小时 JWT 鉴权。
- 管理员的用户查询、创建、角色调整、启停和密码重置。
- 默认日报模板；模板字段新增、配置、排序、启停和不可变版本发布。
- 按工作日期创建唯一日报，保存草稿，提交及归档。
- 用户级“提交后自动归档”设置。
- 日报按日期范围、状态分页查询并查看详情。
- 只对已归档日报生成 Excel，兼容不同模板版本的动态字段。
- 按 Asia/Shanghai 的周一至周日生成周报，来源仅限已归档日报。
- 周报编辑、来源追溯和显式确认后的重新生成。
- 企业微信同步入口显示“功能暂未开放”，不产生外部请求。
- 数据库迁移前自动备份和管理员手动整库备份能力。

### 3.2 P1：应交付

- 关键操作确认、成功/失败反馈、可恢复的重试提示。
- 周报生成前展示未归档日报日期和数量。
- 没有归档日报时允许生成空白周报。
- Excel 列名可读、重复标签可消歧。
- 后端启动失败、迁移失败、数据库繁忙时展示可操作提示。

### 3.3 P2：本期不排期

- 日报快速复制、周报保存前预览和周报版本历史。
- 周报 Excel/PDF 导出与日报自定义导出列。
- 企业微信真实授权、同步、重试和结果回写。
- 附件、AI 总结、团队审批、评论、抄送和绩效统计。
- macOS/Linux 发布、云同步和数据库整体加密。

## 4. 核心业务规则

### 4.1 日报

1. 同一用户、同一 `work_date` 只能有一份日报。
2. 状态只允许 `draft -> submitted -> archived`；开启自动归档时，提交事务最终直接落到 `archived`。
3. 只有草稿可编辑；已提交仅可归档；已归档完全只读且 V1 不支持撤回。
4. 可补写历史和未来日期，但唯一性规则始终生效。
5. 创建日报时固化模板版本和完整字段快照；后续模板变更不得改变历史日报。
6. 提交时由服务端依据模板快照校验必填项与字段类型。

### 4.2 模板

1. 每个用户一套当前模板，发布新配置时生成不可变版本，不原地修改历史版本。
2. 默认核心字段为“今日工作内容”和“明日工作计划”；可改显示名称和顺序，不可删除，且至少启用一个核心字段。
3. V1 字段类型：单行文本、多行文本、数字、日期、单选、多选；不含附件。
4. `field_key` 创建后不可变，显示名称变化不影响导出列合并和历史追溯。

### 4.3 周报

1. 自然周固定为 Asia/Shanghai 周一至周日；`week_start` 必须是周一。
2. 同一用户、同一 `week_start` 只保留一份当前周报。
3. 只汇总该周已归档日报；草稿和已提交未归档日报只用于缺失提示。
4. 周报包含按日期汇总的自动内容，以及“本周补充、下周计划、问题风险”编辑区。
5. 人工编辑不反写日报。重新生成必须显式确认，并覆盖当前自动内容和人工编辑内容。

### 4.4 导出

1. 每份日报一行，只允许当前用户的已归档日报进入导出文件。
2. 基础列在前，动态字段按稳定 `field_key` 合并；同名标签追加字段短标识。
3. 显式选择中含不可导出记录时整体拒绝并列出问题 ID，不静默忽略。

## 5. 非功能需求

| 维度 | 验收要求 |
|---|---|
| 平台 | V1 在 Windows 10/11 x64 安装、运行和升级 |
| 性能 | 个人常规数据量下常用查询/保存 2 秒内反馈；耗时导出显示处理中 |
| 安全 | 后端仅监听 `127.0.0.1`；JWT 与运行期密钥双重校验；密码 Argon2id；Token 使用 `safeStorage` |
| 隔离 | 所有业务查询在 Repository 层按当前用户过滤，越权资源不得泄露存在性 |
| 一致性 | 唯一约束、状态机、乐观锁和事务共同防止重复创建与旧数据覆盖 |
| 可恢复 | 迁移前备份；失败不错误推进状态；数据库繁忙可安全重试 |
| 可维护 | 前后端契约、错误码、模板稳定标识和模块依赖保持稳定 |
| 可观测 | 请求 ID 串联日志；不记录密码、Token、密钥和完整工作正文 |

## 6. 关键验收场景

- Given 尚无用户，When 首次初始化，Then 原子创建首个 admin 和默认模板，重复初始化失败。
- Given 密码已修改或账号已禁用，When 使用旧 Token，Then 返回 Token 失效且不泄露数据。
- Given 同日已有日报，When 重复创建，Then 不产生第二条记录并返回已有日报 ID。
- Given 草稿缺少必填字段，When 提交，Then 保持草稿并返回字段级错误。
- Given 自动归档已开启，When 合法提交，Then 提交和归档时间在同一事务内写入。
- Given 模板发布了新版本，When 查看旧日报，Then 字段、顺序、标签和值仍按旧快照展示。
- Given 导出跨多个模板版本，When 生成 Excel，Then 所有历史字段按 `field_key` 合并且值不丢失。
- Given 跨年自然周，When 生成周报，Then 周范围和日报归属正确。
- Given 周报已被人工修改，When 未确认重生成，Then 系统拒绝覆盖。
- Given 用户访问他人资源 ID，When 查询或修改，Then 返回 404 且不泄露内容。

## 7. 已采用默认决策

以下事项尚无独立业务确认，但已由技术方案指定默认值，开发按此执行；改变任一项均需走架构变更流程：

| ID | 决策 |
|---|---|
| D-01 | 首发平台仅 Windows 10/11 x64 |
| D-02 | 周报重生成经确认后覆盖，不保留版本 |
| D-03 | admin 默认无权查看其他用户业务内容 |
| D-04 | V1 不做 SQLite 整库加密 |
| D-05 | 手动整库备份仅 admin 可执行；备份包含全体用户数据，界面必须提示敏感性 |

## 8. 需求变更规则

- P0/P1 范围、状态机、数据所有权、模板快照、周报来源口径的变更必须先更新本文件及相关架构文档。
- 任何 Agent 不得通过“顺手实现”引入 P2 能力或改变默认决策。
- 需求不清时在 `task.md` 将任务标为 `BLOCKED` 并记录问题，不以代码假设替代业务确认。
- 只有代码、测试和阶段质量门禁共同提供证据后，才能在 `progress.md` 或 `task.md` 将能力标记为已完成。
