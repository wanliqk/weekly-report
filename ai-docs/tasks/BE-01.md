## 1. 任务目标

在 backend/ 内建立一个依赖锁定、类型可检查、可自动测试的 Python 3.12 FastAPI 最小工程，为后续 API 基础设施、数据库、认证和 Electron sidecar 对接提供稳定后端入口。

本任务只建立“可启动、可探活、可检查”的后端骨架：

1. 使用 uv 管理 Python 项目、虚拟环境、生产依赖、开发依赖和 uv.lock。
2. 创建 FastAPI 应用工厂/入口及 GET /health。
3. 确保后端只能以单 worker 方式绑定 127.0.0.1；端口由启动命令或后续 Electron 动态传入，不在源码硬编码。
4. 配置 Ruff、mypy、pytest 和 httpx 最小质量链路。
5. 提供 Windows pwsh 可执行的安装、检查、测试和启动说明。

本任务不实现统一中间件、数据库、认证、业务路由或 sidecar 管理。

## 5. 验收标准

### 5.1 环境与依赖

- 使用 Python 3.12；pyproject 明确拒绝未经验证的 3.13+。
- uv sync --frozen 在干净 backend 环境成功，且不改写 uv.lock。
- 没有 requirements.txt、Pipfile、Poetry lock 或第二套依赖真源。
- 运行/开发依赖分组清晰，没有提前引入数据库、认证、Excel 或业务依赖。

### 5.2 应用启动

- 从 backend/ 执行 Uvicorn 命令可成功导入 app.main:app。
- 服务只绑定 127.0.0.1，显式 workers=1。
- 端口从启动参数传入，源码中不存在固定业务端口。
- 终止命令后进程正常退出，不创建数据库、日志或用户数据目录。

### 5.3 健康检查

- GET /health 返回 HTTP 200 和冻结的成功体结构。
- Content-Type 为 application/json，响应包含 Cache-Control: no-store。
- health 测试验证 code、msg、data.status、data.version 和无敏感字段。
- 未提供 JWT/runtime secret 仍可探活；除 /health 外没有业务接口。

### 5.4 质量门禁

- uv run ruff format --check . 通过。
- uv run ruff check . 通过。

- uv run pytest 通过。
- 测试至少覆盖应用实例可创建、/health 成功体和非敏感响应。
- 测试不依赖网络、真实用户目录、Electron 或生产环境变量。

### 5.5 架构与范围控制

- 仅修改 backend/** 和自己的执行记录。
- 没有 ORM、数据库、认证、CORS、业务 Service/Repository 或 Electron 代码。
- 没有将 FastAPI 绑定到 0.0.0.0，也没有多 worker 配置。
- 应用结构允许 BE-02 增加 core/异常/日志，允许 DB-01 增加 models/repositories/migrations，而无需重写入口。
